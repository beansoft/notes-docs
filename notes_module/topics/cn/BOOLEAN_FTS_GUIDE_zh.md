# 全文布尔搜索

笔记搜索栏中有一个 **全文搜索条件 (AND/OR/NOT)** 开关。开启后，搜索框中的输入会按
[SQLite FTS5](https://www.sqlite.org/fts5.html#full_text_query_syntax) 查询语法解析，而不再是普通关键字——
你可以用布尔运算符组合多个词、用括号分组，以及精确匹配短语。

## 如何开启

1. 打开 **Notes** 工具窗口，点击笔记列表上方的搜索（放大镜）按钮，或按 `Ctrl+F` / `⌘F`，显示搜索栏。
2. 点击搜索框右侧的过滤器图标（**全文搜索条件 (AND/OR/NOT)**）。
3. 输入查询条件。切换开关后结果会立即刷新。

该设置为全局（应用级）设置，重启 IDE 后依然保留。

> 以下两种情况下该开关为**禁用**状态：
> - 项目使用 **Git/Markdown 存储引擎**——该引擎没有 FTS5 索引，仅在默认的 SQLite 存储下可用；
> - 开启了 **“只在标题中搜索”** 选项——该模式按普通子串（SQL `LIKE`）匹配标题，布尔语法不生效。

## 默认模式与布尔模式对比

| | 默认模式（开关关闭） | 布尔模式（开关开启） |
|---|---|---|
| `连接池 配置` | 两个词都必须出现 | 两个词都必须出现（隐式 AND） |
| `AND` / `OR` / `NOT` | 当作普通文字搜索 | 当作运算符 |
| `( )` | 普通字符 | 子表达式分组 |
| `"..."` | 普通字符 | 精确短语 |
| 前缀匹配 | 仅最后一个词 | 每个裸词都自动前缀匹配 |

## 语法

搜索范围同时覆盖笔记的**标题**和**内容**。匹配基于子串（trigram 分词索引），所以搜 `连接池` 也能命中
“数据库连接池配置”；英文不区分大小写。

| 语法 | 示例 | 含义 |
|---|---|---|
| 空格（隐式 AND） | `连接池 配置` | 同时包含 “连接池” 和 “配置” |
| `AND` | `连接池 AND 配置` | 同上，显式写法 |
| `OR` | `数据库 OR 缓存层` | 包含任意一个词 |
| `NOT` | `连接池 NOT mysql` | 包含 “连接池” 但不包含 “mysql” |
| `( )` | `(react OR vue) AND 组件化` | 分组，控制优先级 |
| `"短语"` | `"连接池配置"` | 精确短语 |
| `NEAR( )` | `NEAR(发送合同 kafka)` | 两个词位置相近（默认距离 10） |
| `NEAR( , N)` | `NEAR(发送合同 kafka, 5)` | 两个词之间最多相隔 N 个单位（见下文） |
| `列名:` | `name:redis` / `code:连接池` | 限定只在标题（`name`）或内容（`code`）中匹配 |
| `*` | `hik*` | 显式前缀；裸词已自动加前缀匹配 |

运算符优先级（FTS5）：`NOT` 最高，其次 `AND`，最后 `OR`。不确定时请加括号：
`react OR vue AND 组件化` 等价于 `react OR (vue AND 组件化)`。

### 示例

```text
连接池 AND 配置                      # 关于连接池配置的笔记
数据库 OR 缓存层                     # 数据库或缓存相关
连接池 NOT mysql                     # 连接池笔记，但排除 MySQL 相关的
(react OR vue) AND 组件化            # React 或 Vue 的组件化笔记
"连接池配置" NOT redis               # 精确短语“连接池配置”，排除 Redis
name:redis AND code:连接池           # 标题含 redis，且内容含“连接池”
发送合同 AND kafka                   # 内容 “下单发送合同和发票kafka” 可被命中
NEAR(发送合同 kafka)                 # “发送合同” 与 “kafka” 位置相近
NEAR(发送合同 kafka, 5)              # 同上，显式指定距离
发票 OR 合同                         # 两字短词也可用 OR
kafka NOT 发票                       # 包含 kafka 但不含“发票”
name:发票                            # 标题中含“发票”
"Spring 事务管理" OR "分布式事务"     # 两个中文短语任选其一
```

## 规则与限制

- **运算符必须大写。** 小写的 `and` / `or` / `not` 会被当作普通单词搜索。
- **支持少于 3 个字符的短词，但有一处差异。** trigram 索引无法匹配少于 3 个字符的词，例如 `js`、`db`，
  或“发票”“合同”“组件”这类两字中文词。查询中出现这类词时，插件会把整个表达式翻译成等价的子串（`LIKE`）搜索：
  `AND` / `OR` / `NOT`、括号、短语以及 `name:` / `code:` 都保持原有含义。
  - 例：`发票 OR 合同` → 包含“发票”或“合同”的笔记。
  - 例：`kafka NOT 发票` → 包含 kafka 但不含“发票”的笔记。
  - 例：`(发票 OR 合同) AND kafka` → 含 kafka，且含“发票”或“合同”。
  - 唯一的差异：此时 `NEAR(...)` 无法计算距离，等同于 `AND`。
- **`NEAR` 的距离按字符计，而不是按词计。** 索引把文本切成相互重叠的 3 字符片段（trigram），
  所以 `N` 大致等于第一个词结尾与第二个词开头之间允许间隔的字符数。例如 `NEAR(react hook, 2)` **无法**命中
  “React Hook”（中间的空格横跨 3 个 trigram），`NEAR(react hook, 5)` 则可以。建议把 `N` 设得宽松一些。
- **非法表达式会静默降级。** 引号或括号不配对、运算符悬空（如 `连接池 AND`）时 FTS5 会拒绝该查询，
  插件改为对原始输入做 `LIKE` 搜索，通常查不到结果。结果异常时请先检查语法。
- 已删除（废纸篓中）的笔记不会出现在结果中。

## 常见问题

| 现象 | 可能原因 |
|---|---|
| 开关是灰色的 | 项目使用 Git/Markdown 存储引擎，或开启了“只在标题中搜索” |
| 什么都查不到 | 运算符写成了小写、`"` 或 `( )` 不配对，或运算符悬空 |
| `NEAR(a b, N)` 漏掉了明显的结果 | `N` 按字符计而非按词计，请调大 |
